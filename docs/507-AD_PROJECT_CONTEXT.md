## 8 给新 Codex agent 的工作原则

1. **沿用项目事实。** 先读三个文件，再依据新任务和实际仓库工作。不要重复向 Ben 索取已经在 content 文件给出的姓名、故事、交接方式或转化目标。
2. **保持范围。** 网站工作优先服务产品 overview、会议联系与招募。不要自动扩展成订单、支付、机器人控制或大型管理平台。
3. **持续推进可做的部分。** 资产、预约 URL 或接收服务缺失时，仍可完成可审阅的页面结构和交互，并保留配置点；确实影响实现选择的信息再集中询问。
4. **分清来源。** 原始用户事实、历史方案、文案建议、概念视觉和真实测试分别处理。新确认的决定应覆盖旧值，并更新对应文件。
5. **保持资产一致。** 真实 CAD 决定机器人外形，不自行发明另一款机器人。用户此次要求媒体待补，不预先生成图片或视频。
6. **如实报告完成度。** 没有真实接收渠道不能显示表单已保存；没有模型不能报告 3D 已接入；没有实测不能报告机器人能力已验证。
7. **交付能接着维护的结果。** 内容、资产和链接配置应易于替换。按新 project 的运行方式说明如何查看结果和哪些项仍待补。

用户偏好实用、直接的沟通，以及能够自主完成的工作。不要停留在方案描述；当新任务授权实施时，应完成授权范围内的实现与适当验证。本文只提供上下文，不替用户发起邮件、会议邀请、申请提交或新的部署任务。
